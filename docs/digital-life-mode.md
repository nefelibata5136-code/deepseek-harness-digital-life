# What digital-life mode does

The term describes a runtime composition, not proof of consciousness.
One persistent identity/primary Session can act, maintain continuity, ask for
advice, rest and participate in changes to its operating environment.

## Native DSH foundations

DSH supplies Agent loop/tool execution, Session persistence/projection, Cordis
plugins/profiles, file/skill interfaces, subagents, experimental scheduling,
compaction engines/policies, Computer Use packages and attachment services.
Those are upstream foundations, not inventions of this project.

## Our extensions

Explicit persona/seat binding, separately accepted activity suggestions,
self-authored mental state, continuity writing, runtime preferences and reviewed
capability acceptance are added here. life_* tools are not default DSH tools.
The Host does not manufacture goals/meaning or require productive work when idle.
Versions, operation admission, budget wire protection, fixed credential-bearing
operations, Vault projection and recovery checkpoints are integration mechanisms.

### Self-authored context_compact

DSH offers a modifiable compaction seam; it does not provide this authorship policy
by default. Our prepare/commit/status/cancel mechanism:

1. Prepares an exact balanced older surface span, original-event closure, digest,
   token measurement and expiring plan.
2. Lets the live persona inspect original sources and write its checkpoint.
3. Queues that exact body. At a safe native step, Host validates Session, range,
   hash, references, size and compaction conditions.
4. Uses native persistence/surface replacement. Status confirms durable completion.
   Stale range, duplicate commit and failed flush do not attest success.

There is no auxiliary summarizer in this path. Explicit legacy summarization
remains only for regression fixtures. Checkpoint visibility changes never rewrite
original events or automatically update long-term memory. Pressure prompting
asks the current author to make room; it does not transfer authorship to Host.

### Schedule and Resident

Native schedule_* persists Session-bound wakes. Resident reads existing continuity,
pending suggestions, schedules and activity. It may continue, rest or arrange
a future native wake. Periodic Resident is Disabled by default.
Revised semantics give one current wake with elapsed time/possible passed windows
after downtime, not a replay of each missed action. Native schedule catch-up differs.
State-board and intention-sampling experiments are not blanket autonomous-life claims.

### Participating in environment changes

A persona can discover code/config, develop candidates, run cheap fixtures and
accept reviewed hashes. Modification, tests, acceptance and publication differ.
Ordinary preference changes cannot silently remove identity, budget or credential
boundaries. Current-byte checkpoint/seal/rollback preserves others' dirty work.

## Design directions

Broader safe runtime self-modification, always-on hosting, portable credential/Vault
isolation, complete profile restore and genuine Dots round trips remain directions.
Experimental code is not a completed universal system.
